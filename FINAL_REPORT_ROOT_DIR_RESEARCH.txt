🔧 THE PROBLEM
═══════════════════════════════════════════════════════════════════════════

MISMATCH DETECTED:
  OmniSharp -s flag:     /mnt/c/.../src/            (solution level)
  Detected root_dir:     /mnt/c/.../CenCoCo.Core.API/  (project level)
  
  → These should be the same!

IMPACT:
  - OmniSharp loads full solution (via -s flag) ✅
  - But Neovim thinks workspace is only one project ❌
  - Cross-project "go to definition" might fail
  - File watchers won't monitor other projects
  - Workspace boundaries are incorrect

ROOT CAUSE:
  nvim-lspconfig's default root_pattern includes *.csproj
  → Stops at project level instead of solution level
  → For multi-project solutions, this is incorrect


✅ THE SOLUTION
═══════════════════════════════════════════════════════════════════════════

FIX: Override root_dir pattern to only look for *.sln

LOCATION: /mnt/c/Users/Administrator/Documents/Projekt/KickStartNeoVim/init.lua
LINE: ~708 (inside omnisharp config)

ADD THIS LINE:
root_dir = require('lspconfig.util').root_pattern('*.sln', 'omnisharp.json'),

BEFORE:
omnisharp = {
  cmd = { ... },
  settings = { ... },
},

AFTER:
omnisharp = {
  cmd = { ... },
  root_dir = require('lspconfig.util').root_pattern('*.sln', 'omnisharp.json'),
  settings = { ... },
},

EFFECT:
  - Detection will skip *.csproj files
  - Continue traversing until *.sln is found
  - Stop at solution level (.../src/)
  - root_dir will match -s flag ✅
