CRITICAL FINDING - STYLECOP NOT SHOWING?
=========================================

Root Cause:
RoslynExtensionsOptions:EnableAnalyzersSupport = false (default)

Solution:
Configure omnisharp.json with:

{
  "RoslynExtensionsOptions": {
    "EnableAnalyzersSupport": true,
    "AnalyzeOpenDocumentsOnly": false
  }
}

Verification:
ps aux | grep omnisharp | grep -v grep
# Should show: RoslynExtensionsOptions:EnableAnalyzersSupport=true

See ROSLYN_QUICK_REFERENCE.md for more details.

KEY CONCEPTS AT A GLANCE
========================

WHAT ARE ROSLYN ANALYZERS?
├─ Code analysis tools built on .NET Compiler Platform
├─ Run during IDE editing and build time
├─ Three categories: IDE (style), CA (quality), SA (StyleCop)
└─ Automatically discovered from NuGet packages

HOW DO THEY WORK?
├─ Source code → Syntax trees + Semantic model
├─ Analyzers discovered via reflection
├─ Analyzer Initialize() registers action callbacks
├─ Actions execute during compilation/editing
├─ Diagnostics reported for violations
└─ LSP sends to editor for display

ANALYZER API CORE TYPES
├─ DiagnosticAnalyzer (abstract base)
├─ AnalysisContext (for registering actions)
├─ SyntaxNodeAnalysisContext (syntax node analysis)
├─ SymbolAnalysisContext (symbol analysis)
├─ Diagnostic (reported violation)
└─ DiagnosticSuppressor (suppress false positives)

ACTION EXECUTION ORDER
├─ Compilation Start
├─ Symbol Start → Symbol/Semantic/CodeBlock Actions → Symbol End
├─ Compilation End
└─ Guaranteed: Start before content, content before end

CONFIGURATION HIERARCHY (Precedence)
├─ 1. Command-line arguments (highest)
├─ 2. Environment variables
├─ 3. omnisharp.json (critical for LSP)
├─ 4. .editorconfig (standard rules location)
├─ 5. .ruleset files
├─ 6. .csproj properties
└─ 7. Analyzer defaults (lowest)

STYLECOP INTEGRATION
├─ Install: NuGet package StyleCop.Analyzers
├─ Discovery: Automatic via reflection
├─ Implementation: DiagnosticAnalyzer subclass
├─ Configuration: .editorconfig or .ruleset
└─ Result: SA warnings appear in IDE/LSP

CRITICAL FOR OMNISHARP/NEOVIM
├─ RoslynExtensionsOptions:EnableAnalyzersSupport must be true
├─ AnalyzeOpenDocumentsOnly should be false
├─ Verify: ps aux | grep omnisharp
└─ Check: :LspInfo in editor

COMMON QUESTIONS ANSWERED
=========================

Q: Why don't StyleCop warnings show in my editor?
A: RoslynExtensionsOptions:EnableAnalyzersSupport = false
   Fix: Set to true in omnisharp.json

Q: How do I enable/disable specific rules?
A: Use .editorconfig: dotnet_diagnostic.SA1116.severity = warning

Q: How do analyzers get discovered?
A: Reflection on NuGet packages - no registration file needed

Q: Can I write custom analyzers?
A: Yes, implement DiagnosticAnalyzer abstract class

Q: How are analyzer actions ordered?
A: Hierarchical: Start before content, content before end
   No order between different action types

Q: How do code fixes work?
A: CodeFixProvider calculates fixes for diagnostics
   Light bulb shows available fixes

Q: What's the configuration precedence?
A: Command-line > env vars > omnisharp.json > .editorconfig > .ruleset > .csproj

Q: How does StyleCop integrate?
A: NuGet package → Automatic discovery → Reflection instantiation → Actions on code

Find detailed answers in ROSLYN_QUICK_REFERENCE.md
