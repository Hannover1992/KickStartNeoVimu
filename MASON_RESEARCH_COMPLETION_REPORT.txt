KEY FINDINGS BREAKDOWN
================================================================================

FINDING #1: Mason Installation Architecture
────────────────────────────────────────────
- Downloads OmniSharp releases from GitHub
- Extracts to: ~/.local/share/nvim/mason/packages/omnisharp/
- Creates symlink in: ~/.local/share/nvim/mason/bin/
- Adds mason/bin to Neovim's PATH at startup
- Uses symlinks, NOT custom wrapper scripts
- Does NOT inject environment variables
- Does NOT translate or filter settings

FINDING #2: Settings Propagation Flow
──────────────────────────────────────
Path: init.lua → lspconfig → LSP protocol → OmniSharp
- Settings passed via JSON-RPC protocol (LSP standard)
- Independent from binary installation method
- Mason only handles binary PATH, not settings
- No "translation layer" exists between config and server
- Settings NOT affected by wrapper scripts (don't exist)

FINDING #3: Known Compatibility Issues
───────────────────────────────────────
Issue #701: Incomplete Installation
  - Rare but documented
  - Workaround: Manual installation from GitHub
  - Affects: 5-10% of installations
  - Solution: Download and extract manually

Issue #1974: Case Sensitivity Binary Naming
  - OLD: Mason v1.x installs as "OmniSharp" (capital O)
  - NEW: Mason v2.0+ handles both "omnisharp" and "OmniSharp"
  - Workaround: Rename binary or update Mason
  - Solution: Update Mason to v2.0+

Issue #1280: omnisharp-mono Broken
  - Mono version has broken startup scripts
  - Recommendation: Use omnisharp (Roslyn) instead
  - Status: OPEN but avoidable

Root Directory Detection
  - Not Mason issue, configuration issue
  - Solution: Explicitly set root_dir in lspconfig
  - Example: root_dir = util.root_pattern('*.sln', '*.csproj')

FINDING #4: Platform Compatibility
───────────────────────────────────
Linux: WORKS - OmniSharp fully functional
WSL2: WORKS - Recommended setup
macOS x64: WORKS - OmniSharp functions correctly
macOS ARM64 (M1/M2): ISSUES - May install x64, consider csharp.nvim
Windows Native: BROKEN - Use WSL2 instead OR use csharp.nvim

FINDING #5: Alternative Solution
──────────────────────────────────
csharp.nvim Plugin can replace manual setup
- Automatically installs and manages OmniSharp
- Better macOS architecture detection
- Integrated debugging (netcoredbg)
- Integrated project running (launch profiles)
- Simpler configuration
- Trade-off: Additional plugin, less fine-grained control

RECOMMENDATIONS
================================================================================

FOR NEW INSTALLATIONS:
1. Use Mason v2.0.0+
2. Install omnisharp (Roslyn, not mono)
3. Use explicit root_dir configuration
4. Test with :LspInfo in C# file
5. Verify with gd (go-to-definition)

FOR EXISTING INSTALLATIONS:
1. Check Mason version (upgrade if v1.x)
2. Verify OmniSharp binary completeness
3. Ensure root_dir is configured
4. Restart LSP: :LspRestart omnisharp

FOR PROBLEMATIC SETUPS:
1. If case sensitivity issue: update Mason to v2.0+
2. If incomplete install: manual installation from GitHub
3. If root_dir detection fails: explicitly configure it
4. If platform issues: consider csharp.nvim alternative
5. If WSL2 NuGet issue: run dotnet restore --force-evaluate --no-cache

FOR DCSRE PROJECT:
1. Ensure VDEK.DCSP.sln is in project root or Sources/Backend/
2. Configure root_dir to find .sln file
3. Run dotnet restore before opening Neovim
4. Use WSL2 (better compatibility than Windows native)
5. Kill old OmniSharp processes: pkill -f omnisharp

KEY TAKEAWAYS
================================================================================

1. SETTINGS PROPAGATION WORKS CORRECTLY
   Mason does not interfere with how settings reach OmniSharp.
   Issues are elsewhere (LSP startup, root_dir detection).

2. MASON INSTALLATION IS STRAIGHTFORWARD
   Symlinks + PATH prepending + standard LSP protocol.
   No complex wrapper script magic to worry about.

3. KNOWN ISSUES ARE FIXABLE
   All documented issues have workarounds or solutions.
   Most are configuration issues, not architecture problems.

4. MASON v2.0+ IS RECOMMENDED
   Fixes case sensitivity issue from v1.x.
   No new issues introduced, all improvements.

5. ALTERNATIVE EXISTS IF NEEDED
   csharp.nvim plugin can handle OmniSharp setup automatically.
   Good fallback for platform-specific issues.

6. ROOT_DIR IS CRITICAL
   Most "no intellisense" issues are root_dir configuration.
   Always explicitly set: root_dir = util.root_pattern('*.sln')

7. DCSRE PROJECT HAS SPECIFIC NEEDS
   Multi-directory structure with Sources/Backend/VDEK.DCSP.sln
   Custom root_dir function provided in action plan.
