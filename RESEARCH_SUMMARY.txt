ANSWER TO EACH RESEARCH QUESTION
=================================

Q1: HOW DO ROSLYN ANALYZERS WORK?

Answer: Complete execution pipeline
├─ Source code parsed into syntax trees
├─ Analyzers discovered via reflection from NuGet packages
├─ Analyzer Initialize() method called once per compilation
├─ Analyzer registers action callbacks for specific code elements
├─ Actions execute as code structures are encountered
├─ Diagnostics reported for violations found
├─ Results sent to IDE/build system/LSP client
└─ Editor displays squiggles and suggestions

Key insight: Declarative action registration enables safe parallelization
- Single analyzer actions never concurrent (thread-safe by default)
- Different analyzers run in parallel (framework handles synchronization)

Q2: WHAT IS THE ANALYZER API SURFACE?

Answer: Well-defined core types:

DiagnosticAnalyzer (abstract base)
├─ Initialize(AnalysisContext) - Register action callbacks
└─ SupportedDiagnostics - Array of DiagnosticDescriptor

AnalysisContext (for registering)
├─ RegisterSyntaxNodeAction() - Watch for specific AST nodes
├─ RegisterSymbolAction() - Watch for specific symbols
├─ RegisterSemanticModelAction() - Analyze entire files
├─ RegisterCodeBlockStartAction() - Start of methods/properties
├─ RegisterCompilationStartAction() - Start of compilation
└─ EnableConcurrentExecution() - Performance optimization

SyntaxNodeAnalysisContext (during action execution)
├─ Node - The AST node being analyzed
├─ SemanticModel - Type and symbol information
└─ ReportDiagnostic(Diagnostic) - Report violations

CodeFixProvider (for automated fixes)
├─ FixableDiagnosticIds - Which diagnostics I can fix
└─ RegisterCodeFixesAsync() - Calculate and offer fixes

Q3: HOW DO THIRD-PARTY ANALYZERS INTEGRATE?

Answer: StyleCop.Analyzers example shows the pattern:

1. Install NuGet package: StyleCop.Analyzers 1.1.118
2. Package contains DiagnosticAnalyzer implementations (SA rules)
3. Compiler automatically discovers via reflection
4. Compiler creates instances and calls Initialize()
5. Analyzers register actions for code patterns (parameters, spacing, etc.)
6. During analysis, actions fire and report StyleCop violations
7. Configuration via .editorconfig or .ruleset files
8. IDE displays violations as squiggles

Key insight: NO SPECIAL CODE NEEDED - just package discovery + API implementation

Q4: WHAT IS THE ANALYZER EXECUTION LIFECYCLE?

Answer: Hierarchical order with guarantees:

Compilation Start (first)
  └─ Symbol Start
      ├─ Symbol Actions
      ├─ Semantic Model Actions
      ├─ Code Block Start
      │  ├─ Syntax Node Actions (most granular)
      │  └─ Code Block End
      └─ Symbol End
Compilation End (last)

Guarantees:
- Start actions execute BEFORE content actions
- Content actions execute BEFORE end actions
- NO order guarantee between different action types
- Enables safe, efficient parallelization

Q5: HOW DO YOU ENABLE/DISABLE ANALYZERS?

Answer: Multi-level configuration hierarchy:

Level 1 (Highest): Command-line arguments
Level 2: Environment variables
Level 3: omnisharp.json (critical for LSP/Neovim)
Level 4: .editorconfig (standard location for rules)
Level 5: .ruleset files (complex scenarios)
Level 6: .csproj properties
Level 7: Analyzer defaults (lowest)

Specific methods:
├─ EditorConfig: dotnet_diagnostic.SA1116.severity = warning|error|silent|none
├─ Ruleset: <Rule Id="SA1116" Action="Warning" />
├─ Source code: #pragma warning disable SA1116
├─ Project file: <AnalysisMode>All</AnalysisMode>
└─ Command-line: /p:EnableNETAnalyzers=true /p:AnalysisMode=All

KEY FINDINGS - WHY STYLECOP DOESN'T SHOW IN OMNISHARP/NEOVIM
============================================================

Root Cause: RoslynExtensionsOptions:EnableAnalyzersSupport must be TRUE

Default behavior: OmniSharp silently skips analyzer diagnostics if not enabled

Solution: Configure omnisharp.json:
{
  "RoslynExtensionsOptions": {
    "EnableAnalyzersSupport": true,         <-- CRITICAL
    "AnalyzeOpenDocumentsOnly": false,      <-- Analyze all docs
    "EnableImportCompletion": true
  }
}

Verification:
ps aux | grep omnisharp
# Should show: RoslynExtensionsOptions:EnableAnalyzersSupport=true

If not showing:
- Check omnisharp.json location (project root or ~/.omnisharp/)
- Check .csproj has StyleCop.Analyzers package reference
- Kill OmniSharp: pkill -f omnisharp
- Restart editor
- Check :LspInfo in editor for config confirmation

ARCHITECTURAL INSIGHTS
======================

1. Automatic Discovery
   - Roslyn uses reflection to find analyzers
   - No registry or manifest required
   - Enables third-party extensibility
   - NuGet packages are primary distribution mechanism

2. Immutable Data Structures
   - Syntax trees are immutable (thread-safe)
   - Enables concurrent access without synchronization
   - Multiple analyzers can safely analyze simultaneously

3. Declarative Action Registration
   - Analyzers declare what they analyze
   - Framework handles traversal and invocation
   - Enables optimization without analyzer code changes

4. Hierarchical Configuration
   - Multiple sources merged with clear precedence
   - Command-line can override files
   - Prevents configuration surprises

5. Extensibility Points
   - DiagnosticAnalyzer - Custom analysis logic
   - DiagnosticSuppressor - False positive suppression
   - CodeFixProvider - Automated fixes
   - FixAllProvider - Batch operations

CRITICAL CONFIGURATION FOR LSP USERS
====================================

omnisharp.json must contain:
{
  "RoslynExtensionsOptions": {
    "EnableAnalyzersSupport": true,
    "AnalyzeOpenDocumentsOnly": false
  }
}

Without this:
- StyleCop warnings WILL NOT appear
- OmniSharp runs without analyzer diagnostics
- Only compiler diagnostics shown

With this:
- StyleCop warnings appear in editor
- All analyzer diagnostics included
- Full LSP diagnostic experience

CONCLUSION
==========

Roslyn analyzers are a sophisticated, well-designed system for static code analysis:

1. Automatically discovered from NuGet packages via reflection
2. Execute through declarative action registration
3. Process AST/semantic information safely (immutable structures)
4. Report structured diagnostics with severity levels
5. Integrate seamlessly with IDEs and LSP servers
6. Highly configurable through multiple mechanisms

StyleCop and other third-party analyzers integrate seamlessly using this system.
LSP servers like OmniSharp need explicit configuration to enable analyzer diagnostics.

The documentation provided covers all aspects needed to understand, configure, and
troubleshoot Roslyn analyzers in the context of OmniSharp/LSP/Neovim development.
