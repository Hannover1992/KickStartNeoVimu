KEY FINDINGS
================================================================================

1. HOW ROSLYN INTEGRATES WITH EDITORCONFIG
   
   • Roslyn has FIRST-CLASS EditorConfig support built into the compiler
   • Automatically discovers .editorconfig files by searching upward
   • Flattens EditorConfig settings into command-line arguments
   • Applies at compile time AND in IDE
   • Supports both .editorconfig (per-file) and .globalconfig (project-wide)

2. WHAT CAN BE CONFIGURED VIA EDITORCONFIG
   
   • Code Style Rules (IDE0001-IDE0380+): Formatting, naming, language preferences
   • Language Options (csharp_* and dotnet_* prefixes): Indentation, spacing
   • Code Quality Rules (CA* rules): Security, performance, design rules
   • Analyzer Severity (dotnet_diagnostic.<rule>.severity): warning/error/none
   • Naming Conventions: PascalCase, camelCase, snake_case, etc.

3. HOW EDITORCONFIG AFFECTS ANALYZER BEHAVIOR
   
   • Settings are flattened into command-line arguments
   • Applied during code analysis by Roslyn
   • Can enable/disable rules via severity levels
   • Precedence: command-line > deeper EditorConfig > global config
   • Works for both interactive (IDE) and build-time analysis

4. HOW OMNISHARP ENABLES/DISABLES EDITORCONFIG SUPPORT
   
   • Setting: FormattingOptions:EnableEditorConfigSupport = true/false
   • When enabled: OmniSharp reads .editorconfig files
   • When disabled: EditorConfig ignored, uses built-in defaults
   • Can be set in:
     - omnisharp.json file
     - OmniSharp LSP settings (e.g., init.lua)
     - Command-line arguments
     - Environment variables

5. STYLECOP INTEGRATION
   
   • StyleCop.Analyzers is a standard Roslyn analyzer
   • Uses SA* rule IDs (SA1116, SA1309, etc.)
   • Fully configurable via EditorConfig
   • Requires THREE OmniSharp settings to work:
     a) EnableAnalyzersSupport = true (enable analyzers)
     b) EnableEditorConfigSupport = true (read .editorconfig)
     c) AnalyzeOpenDocumentsOnly = false (analyze full solution)

================================================================================
CRITICAL SETTINGS FOR STYLECOP IN NEOVIM
================================================================================

1. FormattingOptions:EnableEditorConfigSupport = true
   Purpose: Read .editorconfig files
   Impact: Without this, EditorConfig is completely ignored

2. RoslynExtensionsOptions:EnableAnalyzersSupport = true
   Purpose: Enable all Roslyn analyzers including StyleCop
   Impact: Without this, no analyzer warnings appear

3. RoslynExtensionsOptions:AnalyzeOpenDocumentsOnly = false
   Purpose: Scope of analysis
   Impact: false = entire solution, true = only open files

================================================================================
CONFIGURATION HIERARCHY
================================================================================

Command-line options (highest precedence)
    ↓
EditorConfig files in subdirectory (most specific)
    ↓
EditorConfig files in parent directory
    ↓
Global AnalyzerConfig (.globalconfig)
    ↓
Roslyn hardcoded defaults (lowest precedence)

Practical: More specific EditorConfig overrides parent directories

================================================================================
QUICK START (5 MINUTES)
================================================================================

1. Create .editorconfig in solution root:
   root = true
   [*.cs]
   dotnet_diagnostic.SA1116.severity = warning

2. In Neovim init.lua:
   omnisharp = {
     settings = {
       RoslynExtensionsOptions = {
         EnableAnalyzersSupport = true,
       },
       FormattingOptions = {
         EnableEditorConfigSupport = true,
       },
     },
   }

3. Restart:
   pkill -f omnisharp
   rm -rf ~/.cache/nvim/luac/

================================================================================
BEST PRACTICES FOR EDITORCONFIG WITH ROSLYN
================================================================================

DO:
  ✓ Place .editorconfig at repository root
  ✓ Use `root = true` to prevent searching parents
  ✓ Enable EditorConfig in OmniSharp explicitly
  ✓ Define all team standards in .editorconfig
  ✓ Version control .editorconfig in Git
  ✓ Test configuration with :LspInfo
  ✓ Use command-line enforcement in CI/CD

DON'T:
  ✗ Forget to enable FormattingOptions:EnableEditorConfigSupport
  ✗ Assume EditorConfig is automatically read by OmniSharp
  ✗ Mix EditorConfig and omnisharp.json conflicting settings
  ✗ Leave rules at severity = none unintentionally
  ✗ Expect build enforcement without setting severity = error
  ✗ Create .editorconfig without root = true if at repo root

================================================================================
VERIFICATION COMMANDS
================================================================================

Check if .editorconfig exists:
  ls -la /path/to/solution/.editorconfig

Verify OmniSharp configuration:
  nvim /path/to/file.cs
  :LspInfo
  (Look for RoslynExtensionsOptions and FormattingOptions sections)

Check running OmniSharp process:
  ps aux | grep omnisharp | grep -v grep
  (Should show flattened settings like EnableAnalyzersSupport=true)

Clear cache and restart:
  rm -rf ~/.cache/nvim/luac/
  pkill -f omnisharp

Test build with enforcement:
  cd /path/to/solution
  dotnet build -p:EnforceCodeStyleInBuild=true -p:TreatWarningsAsErrors=true

================================================================================
TROUBLESHOOTING QUICK REFERENCE
================================================================================

Problem: EditorConfig not found
Solution: 
  1. Check filename: must be .editorconfig (lowercase, no extension)
  2. Check location: must be in solution root or parent directory
  3. Add root = true to prevent searching parents

Problem: StyleCop warnings not appearing
Solution:
  1. Check EnableAnalyzersSupport = true
  2. Check EnableEditorConfigSupport = true
  3. Check rule severity is not = none
  4. Clear cache and restart OmniSharp

Problem: EditorConfig changes don't take effect
Solution:
  1. rm -rf ~/.cache/nvim/luac/
  2. pkill -f omnisharp
  3. Reopen file in Neovim

Problem: Performance is slow
Solution:
  Set AnalyzeOpenDocumentsOnly = true (analyzes only open files)

================================================================================
TECHNICAL SUMMARY
================================================================================

Roslyn EditorConfig Support:
  • Native first-class support in compiler
  • Automatic discovery via directory search
  • Flattens settings to CLI arguments
  • Precedence-based configuration hierarchy
  • Works for both IDE and build

OmniSharp Configuration:
  • FormattingOptions:EnableEditorConfigSupport enables reading
  • RoslynExtensionsOptions:EnableAnalyzersSupport enables analyzers
  • RoslynExtensionsOptions:AnalyzeOpenDocumentsOnly controls scope
  • Hierarchical: CLI > omnisharp.json > environment > defaults

StyleCop Integration:
  • Standard Roslyn analyzer with SA* rules
  • Fully EditorConfig configurable
  • Requires both analyzer and EditorConfig support enabled
  • Severity controls display level (none/suggestion/warning/error)

CONCLUSION
================================================================================

EditorConfig is a powerful, standardized way to configure code analysis and
formatting rules in Roslyn-based projects. When properly configured in
OmniSharp with three key settings enabled, it enables consistent code style
enforcement across IDE, build, and CI/CD pipelines.

For StyleCop to work in Neovim:
1. Create .editorconfig with rule definitions
2. Enable EnableAnalyzersSupport in OmniSharp
3. Enable EnableEditorConfigSupport in OmniSharp
4. Restart and verify
