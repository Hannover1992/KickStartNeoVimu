✅ OmniSharp DOES work with /mnt/c paths in WSL2
   - Project loads correctly
   - File access works
   - Intellisense functions
   - Analyzer warnings appear (StyleCop works)

⚠️  BUT with significant trade-offs:

   - File locking possible when Windows and WSL2 access simultaneously
   - NuGet cache separate (packages not shared between Windows/WSL2)
   - Case sensitivity edge cases (Windows is case-insensitive, WSL2 is case-sensitive)
   - Symlinks may not work reliably on /mnt/c mounts

KEY FINDINGS (5 Major Discoveries)
================================================================================

FINDING 1: Filesystem Performance (10x Slowness)
  Root Cause: WSL2's DrvFs layer adds overhead for Windows filesystem access
  Impact:     /mnt/c path: 25-30s OmniSharp startup
              /home path:  2-3s OmniSharp startup
  Solution:   Move to native Linux path (~/projects)
  Files:      Research.md § 1, Config Rec § Scenario 2

FINDING 2: NuGet Cache Incompatibility  
  Root Cause: Windows and WSL2 maintain completely separate NuGet caches
  Impact:     Build in Windows → packages not available in WSL2
              Build in WSL2 → packages not available in Windows
  Solution:   Set NUGET_PACKAGES=$HOME/.nuget/packages in ~/.bashrc
  Files:      Research.md § 2, Quick Ref § Key Issues #2

FINDING 3: Case Sensitivity Edge Cases
  Root Cause: Windows filesystem is case-insensitive, WSL2/Linux is case-sensitive
  Impact:     File path lookup failures if casing doesn't match exactly
  Solution:   Use exact Windows path casing, or prefer /home paths
  Files:      Research.md § 3, Quick Ref § Symptoms #7

FINDING 4: File Locking Conflicts
  Root Cause: Windows .NET holds locks that WSL2 OmniSharp cannot break
  Impact:     "File in use" errors when Windows builds while WSL2 accessing
  Solution:   Don't build simultaneously, use 'fixlsp' alias after Windows builds
  Files:      Research.md § 4, Quick Ref § Symptoms #8

FINDING 5: Symlink Unreliability
  Root Cause: OmniSharp may not properly follow symlinks on /mnt/c mounts
  Impact:     Symlinked directories not analyzed, binaries not found
  Solution:   Avoid symlinks on /mnt/c, use actual copies or /home paths
  Files:      Research.md § 5

CRITICAL CONFIGURATION ITEMS
================================================================================

ALWAYS DO (All Scenarios):
  ✓ Set NUGET_PACKAGES="$HOME/.nuget/packages" in ~/.bashrc
  ✓ Use 'dotnet' + OmniSharp.dll (NOT OmniSharp.exe)
  ✓ Use exact Windows path casing (if using /mnt/c)
  ✓ Add fixlsp alias: dotnet restore --force-evaluate --no-cache && pkill -f omnisharp

CRITICAL init.lua Setting:
  cmd = {
    'dotnet',  -- Must be 'dotnet', not 'OmniSharp.exe'
    vim.fn.stdpath('data') .. '/mason/packages/omnisharp/libexec/OmniSharp.dll',
    '-s', vim.fn.expand('~/projects/DCSRE/Sources/Backend'),  -- Use /home or correct /mnt/c
  }

ENVIRONMENT Setup (~/.bashrc):
  export NUGET_PACKAGES="$HOME/.nuget/packages"
  export DOTNET_ROOT="$HOME/.dotnet"
  export PATH="$PATH:$DOTNET_ROOT:$DOTNET_ROOT/tools"
  export DOTNET_SKIP_FIRST_TIME_EXPERIENCE=true
  export DOTNET_CLI_TELEMETRY_OPTOUT=true
  alias fixlsp='dotnet restore --force-evaluate --no-cache && pkill -f omnisharp'

================================================================================
TROUBLESHOOTING QUICK REFERENCE
================================================================================

Problem: OmniSharp won't connect (30+ seconds or fails)
Solution: 
  1. Check path: ls -la ~/projects/DCSRE/Sources/Backend/ (or /mnt/c path)
  2. Clear: pkill -f omnisharp && rm -rf ~/.cache/nvim/luac/
  3. Restore: dotnet restore --force-evaluate --no-cache
  4. Restart Neovim

Problem: "NuGet packages not found"
Solution:
  1. Set NUGET_PACKAGES in ~/.bashrc
  2. Run: fixlsp (or dotnet restore --force-evaluate --no-cache)
  3. Wait for restore to complete
  4. Restart Neovim

Problem: File lock errors ("file in use")
Solution:
  1. Kill builds: pkill -f dotnet
  2. Kill OmniSharp: pkill -f omnisharp  
  3. Clear: fixlsp
  4. Wait 2-3 seconds
  5. Restart Neovim

Problem: Intellisense very slow (2-5 seconds)
Solution:
  1. Check if using /mnt/c: ps aux | grep omnisharp | grep -v grep
  2. If yes, consider moving to /home (Scenario 2)
  3. Or reduce analysis: AnalyzeOpenDocumentsOnly = true in settings
